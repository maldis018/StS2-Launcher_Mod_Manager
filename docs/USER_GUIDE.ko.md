# StS2 Launcher Redux 사용설명서

English: [USER_GUIDE.md](USER_GUIDE.md)

처음 설치하는 사용자를 위한 **StS2 Launcher Redux** 단계별 가이드입니다. 각 단계마다 폰 화면이 어떻게 보이는지 스크린샷과 함께 설명합니다. 원래 StS2 Launcher Mod 용으로 쓴 글이라 일부 스크린샷에는 이전 앱 이름이 보이지만, 사용 방법은 같습니다.

StS2 Launcher Redux는 비공식 팬 프로젝트이며 Mega Crit Games와 관련이 없습니다.

> **검증된 환경**: Galaxy Z Fold7 (메인 + 커버 화면 양쪽). 다른 폼팩터(태블릿 등)는 [이슈 #6](https://github.com/iunius612/StS2-Launcher_Mod_Manager/issues/6) 참조.

## 1. APK 다운로드 + 설치

[Releases 페이지](https://github.com/maldis018/StS2-Launcher_Mod_Manager/releases/latest)에서 가장 최신 버전의 `StS2LauncherRedux-vX.Y.Z.apk` 파일을 폰으로 다운로드합니다.

  <img src="images/1.jpg" width="600">

설치 시 **"출처를 알 수 없는 앱"** 허용이 필요할 수 있습니다. 폰 브라우저나 파일 매니저가 처음 APK를 설치할 때 한 번씩 권한 요청 다이얼로그가 뜹니다.

  <img src="images/2.jpg" width="600">

> **업그레이드 시**: 같은 keystore로 서명된 빌드를 위에 덮어 설치하면 세이브, Steam 로그인, 받아 둔 게임(약 3GB)이 모두 보존됩니다. 0.5.0에서 0.5.1 같은 마이너 업그레이드는 데이터가 그대로 유지됩니다.

## 2. 첫 실행: 권한 부여

런처를 처음 실행하면 **"모든 파일 액세스 (All files access)"** 권한을 요청합니다.

  <img src="images/3.jpg" width="600">

이 권한이 필요한 이유는:
- 모드 폴더 (`/storage/emulated/0/StS2LauncherRedux/Mods/`)에 사용자가 직접 모드를 넣을 수 있어야 하고,
- 로컬 백업(세이브 백업)이 외부 저장 공간에 세이브 스냅샷을 저장해야 하기 때문입니다.

권한 부여 화면에서 토글을 켜고 뒤로가기를 누르면 런처로 복귀합니다.

  <img src="images/4.jpg" width="600">

## StS2 Launcher Mod에서 옮겨오기

Redux는 별도 앱(패키지 `dev.aldis.sts2launcherredux`, 폴더 `/storage/emulated/0/StS2LauncherRedux/`)이라 StS2 Launcher Mod나 Ekyso의 StS2 Launcher를 대체하지 않고 나란히 설치되며, 서로 데이터를 공유하지 않습니다.

안드로이드는 다른 앱의 내부 데이터를 읽지 못하게 하므로 다음은 이전 앱에 남습니다:

- **Steam 로그인**: Redux에서 다시 로그인하세요.
- **받은 게임 (약 3GB)**: Redux에서 다시 받으세요.
- **현재 세이브**: Steam 클라우드에서 돌아옵니다. Steam 클라우드를 쓰지 않았다면 옮기기 전에 이전 앱에서 **로컬 백업**을 누르세요.

이전 공유 폴더의 내용은 모두 가져올 수 있습니다. 첫 실행 시 (모든 파일 액세스 허용 후) Redux가 `/storage/emulated/0/StS2LauncherMM/`의 모드, 비활성 모드, `mod_config.json`, 로컬 백업, LAN 설정을 복사할지 묻습니다. 복사만 하며 이전 폴더는 바꾸지 않고, 새 폴더에 이미 있는 내용은 덮어쓰지 않습니다. 로그는 가져오지 않습니다.

나중에 다시 실행하려면 **모드 관리 > 로컬 > StS2LauncherMM에서 가져오기**를 여세요.

## 3. Steam 로그인

로그인 화면에는 QR 코드가 표시됩니다. 방법은 두 가지입니다.

### 다른 휴대폰이나 태블릿으로 로그인 (권장)

1. 다른 기기에서 Steam 앱을 열고 **Steam Guard** 탭의 QR 스캐너를 엽니다.
2. 런처 화면의 QR 코드를 스캔하고 Steam 앱에서 로그인을 승인합니다.

비밀번호를 입력하지 않으므로 런처는 비밀번호를 다루지 않습니다. 코드가 만료되거나 승인을 거부하면 **새 코드 받기**를 눌러 다시 시도하세요.

### 이 휴대폰만 있을 때

1. **이 휴대폰에서 로그인**을 누릅니다.
2. Steam 계정 이름과 비밀번호를 입력하고 **로그인**을 누릅니다.
3. Steam 모바일 앱이 있으면 앱에 로그인 승인 요청이 옵니다. 승인하면 됩니다. 앱이 없으면 이메일 등으로 받은 Steam Guard 코드를 입력합니다.

비밀번호는 Steam에 한 번만 전송되며 저장되지 않습니다. QR 로그인으로 돌아가려면 **다른 기기에서 QR 코드로 로그인**을 누르세요.

  <img src="images/5.jpg" width="600">

### Steam Guard 코드 입력 시 주의사항

이 휴대폰에서 로그인할 때 2단계 인증 코드를 받기 위해 다른 앱 (Steam 모바일 앱 등)으로 전환하면 **인증 세션이 약 5~10초만 백그라운드에 있어도 실패 처리**되어 처음부터 다시 입력해야 합니다.

  <img src="images/6.jpg" width="600">

**대처법**:
- **팝업/포커스 모드**: Steam 모바일 앱을 팝업 창으로 띄워서 코드를 확인 → 즉시 런처를 다시 터치해 포커스 유지.
- **분할 화면**: 런처와 Steam 앱을 동시에 띄워서 한쪽 보고 다른 쪽 입력.

  <img src="images/7.jpg" width="600">

## 4. 브랜치 선택 + 게임 다운로드

로그인 성공 후 게임 파일이 없는 상태라면 **브랜치 선택 화면**이 표시됩니다.

  <img src="images/8.jpg" width="600">

> **PC와 같은 브랜치를 선택하세요.** 모바일에서 베타 브랜치 진행도를 PC의 일반 브랜치로 가져갈 수 없고, 그 반대도 마찬가지입니다 (Steam 클라우드 동기화 충돌 발생). 자세한 내용은 FAQ 참조.

브랜치를 고르고 다운로드 버튼을 누르면 약 **3GB**의 게임 파일이 다운로드됩니다. 와이파이 권장.

  <img src="images/9.jpg" width="600">

다운로드 중에는 **일시정지**로 멈출 수 있고, 받은 부분은 그대로 남습니다. 이후 **이어받기**를 누르면 멈춘 곳부터 계속 받습니다. 연결이 끊기거나 앱이 종료되어도 다음에 이어서 받을 수 있습니다. 화면을 끄면 다운로드가 멈출 수 있으니 다운로드가 끝날 때까지 화면을 켜 두는 것이 좋습니다.

## 6. 게임 시작

런처 화면에서 **게임 시작**을 누르면 **Steam 클라우드와 진행도를 확인**하는 단계가 먼저 진행됩니다.
잠시 검은 화면이 나오지만, 세이브 관리가 클라우드에서 파일을 내려받는 중이니 기다려 주세요.
(30초에서 1분을 넘기면 네트워크 지연이나 버그를 의심해 보세요.)

  <img src="images/11.jpg" width="600">

확인 결과에 따라 다음 중 하나가 일어납니다:

- **양쪽 진행도 일치 또는 데이터 없음**: 즉시 게임 메인 메뉴로 진입 (다이얼로그 안 뜸).
- **한쪽에만 진행도 있음 또는 양쪽 다름**: **세이브 관리 다이얼로그**가 자동으로 표시됨 [9번](#9-세이브-관리-다이얼로그-사용법) 참조.

첫 실행 시에는 게임이 셰이더를 스캔하고 압축을 해제합니다.

  <img src="images/12.jpg" width="600">

셰이더 업데이트가 끝나면 잠시 후 런처 메인 화면으로 복귀합니다.

이후 게임에 진입하면 일반적인 Slay the Spire 2 플레이 흐름과 같습니다.

> 게임 종료 시 (게임 메뉴 > Quit) 런처가 클라우드 업로드 대기열이 빌 때까지 (최대 5분, 보통 1~5초) 기다립니다. 이 동안 프로세스는 백그라운드에 살아 있고 Steam 네트워크 트래픽이 보일 수 있습니다. 정상 동작입니다.

## 7. 게임 업데이트 확인 / 브랜치 변경

> **게임과 런처 확인은 별도 버튼입니다.** **게임 업데이트 확인**(이 섹션)과 **런처 업데이트 확인**([13번](#13-런처-업데이트-확인))은 각자의 버튼, 결과, 다이얼로그를 가집니다.

이미 게임을 다운로드한 상태라도 **게임 업데이트 확인** 버튼을 누르면 브랜치 선택 화면이 다시 열립니다. 다른 브랜치(예: `public`에서 `public-beta`로)로 갈아타고 싶을 때 사용하세요.

  <img src="images/13.jpg" width="600">

### 브랜치 변경 시 주의사항

- **새 브랜치는 전체 재다운로드** (약 3GB). 델타 다운로드는 일부러 쓰지 않습니다. 브랜치 간 바이너리가 바이트 단위로 호환되지 않을 수 있어서입니다.
- **세이브 / Steam 로그인 / 모드 설정은 보존**됩니다. 게임 파일 (`game/`, `download_state/`)만 새로 받습니다.
- **PC와 브랜치를 일치시키세요.** 다른 브랜치끼리는 Steam 클라우드 동기화가 충돌할 수 있습니다. [FAQ](#15-자주-묻는-질문-faq)의 브랜치 일치 항목을 참조하세요.

### 카드, 유물, 포션 이미지가 잘못 보일 때: 이미지 캐시 삭제

게임 업데이트 후 **카드 / 유물 / 포션** 등의 아이콘이 다른 이미지로 잘못 표시되는 경우, 모바일용 텍스처 캐시(ETC2 압축본)가 옛 빌드 기준으로 남아 있어 발생합니다. 회복 방법은 두 가지입니다.

**자동 (대부분의 케이스에서 사용자 개입 불필요)**

  <img src="images/29.jpg" width="600">

게임 업데이트(PCK 파일 갱신)가 감지되면 다음 앱 실행 시 자동으로 텍스처 캐시를 재생성합니다. 로딩 화면("이미지 캐시를 다시 만드는 중입니다")이 30~60초 표시되며, 끝나면 정상 진입합니다. 세이브 / 진행도 / 로그인 정보는 모두 보존됩니다.

  <img src="images/30.jpg" width="600">

**수동: 이미지 캐시 삭제 버튼**

  <img src="images/31.jpg" width="600">

자동 감지가 놓친 경우나 직접 캐시를 비우고 싶을 때 사용합니다:

1. 메인 화면에서 **게임 업데이트 확인**을 누릅니다.
2. 브랜치 선택 화면 **오른쪽 아래**에 있는 작은 회색 **이미지 캐시 삭제** 버튼을 누릅니다.
3. 확인 다이얼로그가 작업 내용, 다음 실행이 30~60초 더 걸린다는 안내, 보존되는 항목을 알려 줍니다.
4. **삭제**를 누르면 앱이 재시작되고, 위 자동 흐름과 같은 로딩 화면이 나옵니다.

**보존되는 것과 재생성되는 것:**

| 항목 | 동작 |
|---|---|
| 게임 PCK / 다운로드 데이터 (`game/`, `download_state/`) | **보존**: 재다운로드 없음 |
| 세이브 / 진행도 (`steam/<userId>/...`) | **보존** |
| Steam 로그인 / 자동 동기화 설정 | **보존** |
| 로컬 백업 스냅샷 (`StS2LauncherRedux/Saves/`) | **보존**: 외부 저장 공간에 있어 캐시 정리와 무관 |
| 모바일용 텍스처 캐시 (`etc2_cache/.godot/imported/`) | **재생성** (약 30~60초) |

예전 회복 방법이었던 "앱 데이터 삭제 후 재설치"와 같은 효과를, 게임을 다시 받지 않고 얻을 수 있습니다. 자세한 내용은 [issue #23](https://github.com/iunius612/StS2-Launcher_Mod_Manager/issues/23) 참조.

## 8. 자동 동기화 토글

런처 메인 화면의 **자동 동기화: 켜짐 / 꺼짐** 토글로 Steam 클라우드 자동 동기화를 끄거나 켤 수 있습니다.

  <img src="images/14.jpg" width="600">

| 상태 | 동작 |
|---|---|
| **자동 동기화: 켜짐** (기본) | 게임 진행 중 세이브가 Steam 클라우드에 자동으로 올라가고, 다음 게임 시작 때 다이얼로그로 확인 |
| **자동 동기화: 꺼짐** | 클라우드와 분리됨. 세이브는 폰에만 저장되고 다른 기기(PC 등)와 동기화되지 않음 |

### 언제 꺼 두나?

거의 항상 켜 두기를 권장합니다. 끄는 것이 필요한 특수 상황:

- **임시 디버깅**: 클라우드 측 동기화가 의심스러울 때 끄고 폰에서만 진행한 뒤, 다시 켜고 세이브 관리에서 정확히 결정.
- **PC와 의도적으로 다른 진행을 원할 때**: 모바일에서 별도 캐릭터나 런을 진행하고 PC는 그대로 두고 싶을 때. 다시 켜면 충돌 다이얼로그가 뜨므로 그때 결정해야 합니다.

꺼 두었다가 다시 켜면 **세이브 관리가 자동으로 충돌을 검출**해 어느 쪽을 유지할지 묻습니다. 다이얼로그는 다음 게임 시작 시점에 뜹니다.

## 9. 세이브 관리 다이얼로그 사용법

Steam 클라우드와 폰 사이에 진행도 차이가 감지되면 다이얼로그가 자동으로 표시됩니다. 런처 화면에서 **세이브 관리**를 직접 탭하면 언제든지 현재 동기화 상태를 확인할 수도 있습니다.

### 다이얼로그 구성

각 카드는 한 프로필의 진행도 정보를 보여줍니다.

| 항목 | 의미 |
|---|---|
| **프로필 N** (부제) | 카드가 어느 프로필 데이터인지 (1, 2, 3 또는 모드 프로필) |
| **최근** 배지 | 두 카드 중 더 최근에 변경된 쪽 (progress.save와 current_run.save 중 수정 시각(mtime)이 더 최근인 쪽) |
| **마지막 수정 / 파일 크기** | progress.save의 수정 시각(mtime) / 크기 |
| **총 플레이 시간** | 누적 플레이 시간 |
| **현재 진행** | 진행 중인 런이 있으면 `1막 3층` 같이 표시, 없으면 대시 모양의 자리 표시 |
| **전적 / 최고 승천 / 올라간 층 / 발견 유물** | progress.save의 누적 통계 |

### 상황별 다이얼로그 모습

#### 상황 1: 다름 (conflict)

본문은 "이 기기와 Steam 클라우드의 진행도가 다릅니다. 어느 쪽을 유지할지 선택하세요."이고, 두 카드와 **취소 / 로컬 유지 / 클라우드 유지** 버튼이 나옵니다. 여러 프로필이 동시에 다르면 본문에 `(프로필 N개)`가 붙습니다.

  <img src="images/15.jpg" width="600">

### 어느 쪽을 유지할지 결정 가이드

다이얼로그가 더 최근 쪽 버튼을 자동으로 강조합니다 ("최근" 배지가 붙은 카드의 유지 버튼). 일반적인 결정 흐름:

| 상황 | 선택 |
|---|---|
| 폰에서 방금 진행했고 다른 기기에 전달하려면 | **로컬 유지** |
| PC에서 진행했고 폰으로 가져오려면 | **클라우드 유지** |
| 헷갈리면 | **취소**: 그 세션은 클라우드 동기화 꺼짐, 다음 시작 시 다시 결정 가능 |

> **확신이 없을 때 안전하게**: "현재 진행" 행을 보세요. 두 카드 중 진행 중 런이 있는 쪽 또는 더 진행된 쪽(예: 1막 5층 대 1막 3층)이 보통 사용자가 잃고 싶지 않은 데이터입니다.

#### 상황 2: 양쪽 동일 (Identical)

두 카드의 크기, 통계, 현재 진행이 모두 같습니다. 본문은 "로컬과 Steam 클라우드의 진행도가 일치합니다. 별도 작업이 필요하지 않습니다."이고 닫기 버튼이 나옵니다.

  <img src="images/16.jpg" width="600">

## 10. 클라우드에 올리기 / 받기

**클라우드에 올리기**와 **클라우드에서 받기** 버튼은 강제 동기화 도구입니다. **일반적인 사용에서는 권장하지 않습니다.** 클라우드 동기화는 게임 시작과 종료 시 자동으로 처리되고, 자동 동기화가 깨져도 세이브 관리가 정확한 선택지를 제공하기 때문입니다.

  <img src="images/17.jpg" width="600">

| 버튼 | 동작 |
|---|---|
| **클라우드에 올리기** | 폰의 모든 세이브(progress, current_run, history `.run`, prefs, settings, 모든 프로필 포함)를 Steam 클라우드에 강제로 올림 |
| **클라우드에서 받기** | Steam 클라우드의 모든 세이브를 폰으로 강제로 받음 |

### 언제 사용하나?

특수 상황 한정:

- **세이브 관리가 어떤 이유로 작동하지 않을 때** (다이얼로그 응답 없음 등): 한쪽 방향으로 강제 동기화가 필요할 때.
- **PC에서 진행한 내용을 폰으로 옮길 때**: 보통은 세이브 관리가 처리하지만, 한 번에 모두 받고 싶으면 **클라우드에서 받기**를 쓸 수 있습니다.

> 일반 사용은 **게임 시작 시점의 자동 확인 + 세이브 관리 다이얼로그** 흐름으로 충분합니다.

## 11. 로컬 백업 (세이브 백업)

세이브가 잘못 덮어써졌을 때 되돌릴 수 있도록, 세이브 데이터 전체를 **원래 폴더 구조 그대로** 외부 저장 공간에 복사해 둡니다. 백업은 두 방식으로 만들어집니다.

- **수동 백업**: 런처의 **로컬 백업** 버튼을 누르고 확인하면 현재 세이브 트리 전체를 한 번에 스냅샷합니다. 완료되면 백업된 파일 수, 총 크기, 저장 위치를 결과 다이얼로그로 보여줍니다.

  <img src="images/18.jpg" width="600">

- **자동 백업**: **게임 시작**을 누를 때 진행되는 Steam 클라우드 핸드셰이크에서 실행할 때마다 1회 자동으로 만들어집니다. 로컬과 클라우드가 일치하면 로컬 트리를 한 벌 스냅샷하고, 충돌이 나면 **유지하는 쪽**(kept)과 **버려지는 쪽**(discarded)을 둘 다 백업하므로, 잘못 선택해도 버려진 데이터를 되찾을 수 있습니다.

> 백업 파일명은 **변형하지 않습니다** (`.bak` 같은 꼬리표 없음). 원본 파일명과 폴더 구조 그대로 복사됩니다.

### 저장 위치 / 구조

외부 저장 공간 `/storage/emulated/0/StS2LauncherRedux/Saves/` 아래에 **백업 유형별**로 나뉘고, 그 안에 백업 시각(`<ts>` = `yyyyMMdd_HHmmss`) 폴더가, 다시 그 안에 원본 세이브 트리가 그대로 들어갑니다.

```
StS2LauncherRedux/Saves/
  ├── manual/<ts>/<원본 트리>                       (로컬 백업 버튼 = 수동)
  └── auto/
      ├── <ts>_match/<원본 트리>                     (핸드셰이크: 로컬=클라우드 일치 시)
      └── <ts>_conflict/
          ├── kept/<원본 트리>                       (핸드셰이크 충돌: 유지한 쪽)
          └── discarded/<원본 트리>                  (핸드셰이크 충돌: 버려진 쪽)
```

여기서 `<원본 트리>`는 게임이 쓰는 실제 경로 그대로입니다:

```
steam/<SteamID>/[modded/]profile<N>/saves/<파일명>
   예) steam/76561198xxxxxxxxx/profile1/saves/progress.save
       steam/76561198xxxxxxxxx/modded/profile2/saves/current_run.save
```

(`modded/` 단계는 모드를 켜고 플레이한 프로필에만 붙습니다. 빈 세이브는 스냅샷에 포함되지 않습니다.)

### 보존 정책

- **수동 백업(`manual/`)은 자동으로 지워지지 않습니다.** 의도적으로 만든 백업이므로 직접 정리하기 전까지 남습니다.
- **자동 백업(`auto/`)은 최신 10세트만 유지**되고, 그보다 오래된 세트는 오래된 것부터 자동 삭제됩니다(`<ts>_match` 1개, `<ts>_conflict` 1개가 각각 1세트).

### 회복 방법

1. 런처 화면에서 **세이브 관리**를 누르고 **백업 복원**을 고릅니다. (클라우드 동기화가 꺼져 있으면 같은 버튼이 작은 메뉴를 열고, 거기에 **프로필 복제**와 **백업 복원**이 있습니다.)
2. 복원할 스냅샷을 고릅니다. 폴더의 날짜, 시각, 유형(`_match`/`_conflict`)으로 어느 시점 백업인지 알 수 있습니다.
3. 확인하면 모든 세이브가 그 스냅샷으로 되돌아갑니다. 복원 직전에 현재 세이브가 자동으로 백업되므로 복원 자체도 되돌릴 수 있습니다.
4. 클라우드 동기화가 켜져 있으면 이어서 "클라우드에도 올릴까요?"라고 묻습니다. **올리기**를 고르면 복원한 세이브가 클라우드에도 올라갑니다. **올리지 않기**를 고르면 다음 동기화 때 복원한 세이브와 클라우드가 충돌로 표시되어 직접 결정하게 됩니다.

스냅샷은 세이브 파일의 단순 복사본이라 파일 매니저 (또는 `adb pull`)로 `StS2LauncherRedux/Saves/` 아래를 열어 다른 곳에 보관할 수도 있습니다. 게임의 실제 세이브는 앱 내부 저장소에 있으므로, 복원은 반드시 **백업 복원**을 통해 해야 합니다.

## 12. 모드 설치 (선택)

모드 설치 방법은 두 가지입니다. **창작마당 구독**(권장)과 **수동 설치**입니다. 두 방식은 같은 `Mods/` 폴더를 쓰므로 섞어 써도 됩니다.

### 12-1. 창작마당(Workshop)으로 설치 (권장)

런처 홈 화면에서 **모드 관리** 버튼을 탭하면 **모드 허브**가 열립니다. 창작마당 기능은 Steam 로그인이 되어 있어야 사용할 수 있습니다.

  <img src="images/workshop_1.png" width="600">

모드 허브는 4개 탭으로 구성됩니다:

| 탭 | 기능 |
|---|---|
| **창작마당** | 창작마당 검색·구독. 정렬 (인기순 / 최신순 / 급상승 / 최근 업데이트순 / 평점순) + 태그 필터 + 무한 스크롤 |
| **구독 중** | 구독 중 모드 목록 (Steam 계정과 동기화). 자세히 / 비활성화 / 구독 취소 |
| **로컬** | 수동 설치한 (창작마당 외) 모드 목록 |
| **다운로드** | 다운로드 진행 상황 |

오른쪽 위의 **가로/세로** 토글로 모드 허브 화면을 회전할 수 있습니다 (폰을 세로로 들고 쓸 때 유용).

  <img src="images/workshop_2.png" width="600">

#### 검색과 구독

- 검색은 **제목 / 본문 텍스트 / 창작마당 URL·ID 붙여넣기** 3가지 형식을 지원합니다. 목록에 안 뜨는 (unlisted) 모드도 URL/ID로 직접 조회·구독할 수 있습니다.
- **구독**을 누르면 Steam 계정에 구독이 등록되고 즉시 다운로드가 시작됩니다. 다운로드된 모드는 수동 설치와 같은 `/storage/emulated/0/StS2LauncherRedux/Mods/` 폴더에 저장됩니다.

  <img src="images/workshop_3.png" width="600">

- 설치된 모드의 출처(창작마당 / 수동)와 활성 상태는 `Mods/mod_config.json`에 기록됩니다. 파일 매니저로 직접 열어 확인할 수 있습니다.

  <img src="images/workshop_4.png" width="600">

- **자동 업데이트**: 모드 허브에 들어올 때마다 구독 모드의 업데이트를 확인하고 자동으로 내려받습니다.
- **의존성 안내**: 구독한 모드에 필수 모드(예: BaseLib)가 있으면 목록 모달이 떠서 바로 구독할 수 있습니다.
- **자세히**를 누르면 상세 페이지가 열립니다. 설명, 변경 사항 (창작마당 변경 내역 그대로), 토론, 댓글의 4개 탭이 있습니다. 토론·댓글 본문은 Steam 커뮤니티 페이지를 브라우저로 열어 보여줍니다.

  <img src="images/workshop_7.png" width="600">

> 다운로드가 진행 중일 때 모드 허브에서 나가면 다운로드가 취소됩니다 (나가기 전에 경고 표시).

#### 게임에서 확인

구독한 모드는 수동 설치 모드와 함께 게임의 **설치된 모드** 목록에 나타납니다. 첫 실행이라면 아래 12-3의 "Load mods?" 다이얼로그 흐름과 동일하게 진행하면 됩니다.

  <img src="images/workshop_8.png" width="600">

### 12-2. 모드 비활성화 (비활성화 / 활성화)

**구독 취소를 누르면 모드가 기기에서 삭제**됩니다. 삭제하지 않고 잠시 끄고 싶으면 **비활성화**를 쓰세요. 상황에 맞게 골라 쓰면 됩니다.

| 버튼 | 동작 |
|---|---|
| **비활성화** | 모드를 `StS2LauncherRedux/ModsDisabled/`로 이동: 게임에서만 숨김, 파일은 보존 |
| **활성화** | 즉시 복구 (재다운로드 없음). 보관 중 밀린 업데이트가 있으면 받을지 물어봄 |
| **구독 취소** | 구독 취소 + 기기에서 모드 폴더 삭제 |

  <img src="images/workshop_5.png" width="600">

- 비활성화한 모드는 업데이트를 받지 않습니다.
- 파일 매니저로 `Mods/`와 `ModsDisabled/` 사이에서 폴더를 직접 옮겨도 동일하게 인식됩니다 (디스크 상태가 기준).

### 12-3. 수동 설치 (파일 매니저)

창작마당에 없는 모드는 직접 폴더에 넣습니다:

1. **[ZArchiver](https://play.google.com/store/apps/details?id=ru.zdevs.zarchiver)** (Play Store 무료)를 다운받아 사용을 권장합니다. 삼성 **내 파일** 등 일부 OEM 기본 파일 매니저는 안드로이드 scoped storage 정책 때문에 `/storage/emulated/0/StS2LauncherRedux/` 경로가 보이지 않을 수 있습니다 (실제 테스트로 확인).
2. ZArchiver로 `/storage/emulated/0/StS2LauncherRedux/Mods/` 경로 진입.
3. 모드 폴더 (예: `MyMod/`) 통째로 그 안에 복사. 폴더 내부에는 `.dll`, 선택적 `.pck`, `<ModId>.json` 매니페스트가 있어야 합니다. (PC와 같습니다.)

  <img src="images/19.jpg" width="600">
  <img src="images/20.jpg" width="600">
  <img src="images/21.jpg" width="600">

4. 게임 실행 시 게임 본체의 **"Load mods?"** 다이얼로그가 뜨면 "OK"를 탭하세요. 한 번 선택하면 그 다음부터 자동으로 로드됩니다.

  <img src="images/22.jpg" width="600">

수동 설치한 모드는 모드 허브의 **로컬** 탭과 `mod_config.json`에도 나타나며, 창작마당 모드와 함께 사용할 수 있습니다:

  <img src="images/workshop_6.png" width="600">

### 12-4. 모드 호환성 주의

창작마당으로 모드 접근성이 좋아졌지만, **PC와 모바일은 환경이 구조적으로 달라서** 다음 기능을 포함한 모드는 모바일에서 작동하지 않습니다:

1. **P2P 게임 트래픽** (Steam NetworkingSockets / SDR)
2. **오버레이, Steam Input**: Steam 클라이언트 프로세스의 기능이라 프로토콜 수준에서 구현할 수 없습니다 (예: QuickReload)

모드가 작동하지 않으면 [14번](#14-디버그-로그-디버그-토글)의 디버그 로그와 함께 [이슈](https://github.com/maldis018/StS2-Launcher_Mod_Manager/issues)로 제보해 주세요.

> **모드 세이브 병합 관련**: 게임 업데이트로 세이브 저장 방식이 바뀌면서 **UnifiedSave 모드는 더 이상 사용할 수 없습니다.** 모드 세이브 병합이 필요하면 [SaveMerger](https://steamcommunity.com/sharedfiles/filedetails/?id=3748139900)를 사용하세요. 세이브를 건드리는 모드를 쓰기 전에는 [로컬 백업](#11-로컬-백업-세이브-백업)으로 스냅샷을 만들어 두는 것을 권장합니다.

## 13. 런처 업데이트 확인

런처는 APK 자체를 앱 안에서 업데이트할 수 있습니다. 새 버전이 나오면 다이얼로그로 알려 주고, **업데이트**를 한 번 누르면 다운로드, 설치, 앱 재시작까지 진행됩니다.

### 자동 체크 (부팅 시 1회)

런처 부팅 후 실행 화면에 진입하면 자동으로 GitHub `releases/latest`와 비교합니다. 새 버전이 있으면 다이얼로그가 바로 뜨고, 이미 최신이면 아무 알림 없이 넘어갑니다.

  <img src="images/24.jpg" width="600">
  <img src="images/25.jpg" width="600">

### 런처 업데이트 확인 버튼 (수동)

**게임 시작** 버튼 위에 있는 **런처 업데이트 확인** 버튼으로 언제든 직접 확인할 수 있습니다. 결과별 동작:

| 결과 | 동작 |
|---|---|
| **신버전 있음** | "런처 v0.X.Y 업데이트가 있습니다." 다이얼로그가 "지금 다운로드해 설치할까요?"라고 묻고, **업데이트**를 누르면 다운로드 후 설치 |
| **이미 최신** | "이미 최신 버전의 런처입니다." 다이얼로그가 "GitHub 릴리스 페이지를 열어 볼까요?"라고 묻습니다 |
| **체크 실패** (네트워크 등) | "런처 업데이트를 확인하지 못했습니다." 다이얼로그 + 에러 메시지 |

  <img src="images/26.jpg" width="600">

### 첫 사용 시 권한 흐름

처음 다운로드 시도 시 Android가 **이 출처의 앱 설치 허용** (REQUEST_INSTALL_PACKAGES) 토글을 요구합니다 (Android 8 이상):

1. 런처 다이얼로그에서 **설정 열기**를 누르면 시스템 설정 화면으로 이동합니다.
2. **이 출처 허용** 토글을 켜고 뒤로가기를 누릅니다.
3. 런처로 돌아와 **런처 업데이트 확인**을 다시 탭하면 이번에는 다운로드 진행률 다이얼로그가 나옵니다.
4. 다운로드가 끝나면 Android 설치 화면이 열립니다. **업데이트**를 누르면 앱이 재시작됩니다.

> 같은 keystore로 서명되어 있어 세이브, Steam 로그인, 받아 둔 게임(약 3GB)이 모두 보존됩니다.
>
> 릴리스에 APK가 첨부되어 있지 않으면 GitHub 릴리스 페이지를 브라우저에서 여는 방식으로 대체됩니다.

## 14. 디버그 로그 (디버그 토글)

런처에 문제가 발생했을 때 분석에 필요한 logcat 출력을 외부 저장 공간에 캡처할 수 있습니다. 콘솔 옆 **디버그: 켜짐 / 꺼짐** 토글로 제어합니다.

  <img src="images/27.jpg" width="600">

### 동작 방식

- **기본값 켜짐**: 첫 부팅부터 켜져 있어, 런처가 켜지자마자 멎는 경우에도 로그가 남습니다.
- 자기 프로세스의 logcat만 캡처하므로 (`logcat --pid <self>`) 추가 권한이 필요 없습니다.
- **부팅 시 자동 시작**: `onCreate` 단계부터 캡처하므로 .NET / FMOD / BCL 부팅 로그까지 모두 포함됩니다.
- 한 줄마다 바로 파일에 기록하므로 강제 종료나 크래시 후에도 로그가 남습니다.
- 저장 공간이 무한정 늘지 않도록 **최대 20개**만 유지하고, 가장 오래된 것부터 삭제합니다.

### 저장 위치

```
/storage/emulated/0/StS2LauncherRedux/Logs/
  ├── launcher_<YYYYMMDD>_<HHMMSS>.log  (실행할 때마다 새 파일)
  └── ...
```

  <img src="images/28.jpg" width="600">

### 문제 보고 방법

1. 외부 파일 매니저(ZArchiver 권장)로 위 경로를 엽니다.
2. **launcher_*.log** 중 문제가 발생한 시점의 파일(보통 가장 최근 것)을 찾아 PC로 옮기거나 메신저로 보냅니다.
3. 이슈에 첨부해 주세요: [maldis018/StS2-Launcher_Mod_Manager/issues](https://github.com/maldis018/StS2-Launcher_Mod_Manager/issues)

### 디버그 끄기

저장 공간이나 사생활이 걱정되어 로그 캡처를 원하지 않으면 토글을 꺼 두세요. 설정은 SharedPreferences에 저장되어 다음 실행부터 적용되고, 진행 중인 캡처는 즉시 중단됩니다. 다시 켜면 그 시점부터 새 파일에 캡처를 시작합니다. 이미 부팅된 뒤이므로 부팅 직후 로그는 빠지니, 실행부터의 전체 로그가 필요하면 토글을 켜고 앱을 재시작하세요.

## 15. 자주 묻는 질문 (FAQ)

### Q. PC와 모바일 브랜치가 달라도 동기화가 되나요?

경우에 따라 다릅니다.

- **세이브 스키마가 같은 두 브랜치** (예: 마이너 업데이트 차이만 있는 경우)라면 그대로 클라우드 동기화가 작동합니다.
- **스키마 변경이 있는 브랜치 차이** (예: PC가 public, 모바일이 public-beta이고 beta가 새 필드를 추가한 경우) Steam 클라우드가 "동기화 충돌" 다이얼로그를 띄우며 복구가 어려워질 수 있습니다.

**기기 간 전환에서 가장 안전한 절차** (1회 검증):
1. PC Steam에서 StS2 속성의 베타 탭을 열고 **폰과 같은 브랜치**를 선택합니다.
2. PC에서 StS2를 한 번 실행해 메인 메뉴까지 간 뒤 종료합니다. 이 과정에서 PC의 세이브가 새 브랜치 스키마로 클라우드에 올라갑니다.
3. 폰의 런처에서 **게임 시작**을 누릅니다. 세이브 관리 다이얼로그가 클라우드의 새 데이터를 정확히 인식하면 **클라우드 유지**나 자동 흐름으로 받으면 됩니다.

이 절차가 **항상 필요한 것은 아닙니다.** 브랜치 차이가 사소하면 그대로 동기화됩니다. 다만 충돌이 발생했을 때는 이 절차가 표준 복구 경로입니다.

### Q. 클라우드에 잘못된 데이터를 올려 버렸어요. 회복할 수 있나요?

PC에서는 [shrederr/sts2-progress-rebuild](https://github.com/shrederr/sts2-progress-rebuild) 도구가 `.run` 히스토리에서 `progress.save`를 재구성해 클라우드까지 복구합니다.

폰의 로컬만 잘못됐다면 (클라우드는 멀쩡) 세이브 관리에서 **클라우드 유지**를 고르면 회복됩니다.

로컬 백업 스냅샷이 있다면 **세이브 관리 > 백업 복원**에서 복원하세요. 특히 충돌이 날 때마다 **버려진 쪽 데이터**가 별도 스냅샷으로 저장되므로 (**자동 · 충돌(버림)** 배지로 표시, `auto/<ts>_conflict/discarded/`에 저장), **로컬 유지**나 **클라우드 유지**를 잘못 골랐어도 되돌릴 수 있습니다. ([11번](#11-로컬-백업-세이브-백업) 참조)
  <img src="images/23.jpg" width="600">

### Q. 세이브 관리가 매번 "충돌"이라고 떠요.

PC와 모바일이 progress.save를 각자 조금씩 다르게 정규화하는 경우가 있습니다. 통계는 같은데 크기만 매번 수 KB 차이가 납니다. StS2 Launcher Mod 0.3.2에 들어간 파괴적 변경 차단 로직 덕분에 이 경우에도 안전하지만, 다이얼로그는 가끔 한 번씩 뜹니다. 별도로 추적 중입니다.

이때는 **로컬 유지** 또는 **클라우드 유지** 중 눈에 띄게 더 최근인 쪽 (방금 진행한 기기)을 선택하면 됩니다.

### Q. 게임 종료 후 클라우드 업로드에 시간이 좀 걸리는 것 같은데요?

정상입니다. 메뉴 > Quit을 선택하면 런처가 클라우드 업로드 대기열이 완전히 빌 때까지 (최대 5분, 보통 1~5초) 기다립니다. 이 동안 프로세스는 백그라운드에 살아 있고 Steam 네트워크 트래픽이 보일 수 있습니다.

### Q. 폰에서 앱을 스와이프로 강제 종료하면 데이터가 손실되나요?

StS2 Launcher Mod 0.3.2부터는 자동으로 회복됩니다. 스와이프했을 때 클라우드 업로드 대기열이 다 비워지지 않았더라도 다음 부팅 시 `SaveProgressComparer`가 로컬이 더 최근임을 감지해 클라우드에 올립니다.

그래도 **메뉴 > Quit**으로 정상 종료하는 것이 가장 안전합니다.

### Q. 게임 다운로드를 다시 받고 싶어요.

**게임 업데이트 확인**에서 다른 브랜치를 선택하면 자동으로 전체를 다시 다운로드합니다. 같은 브랜치를 다시 받으려면 다른 브랜치를 선택했다가 원래 브랜치를 다시 선택하세요.

## 도움이 되는 명령어 (선택)

폰을 PC에 USB 디버깅으로 연결한 사용자라면:

```bash
# 런처 logcat 보기
adb logcat -s DOTNET:I STS2Mobile:V godot:V

# 외부 저장 모드/세이브 폴더 보기
adb shell ls -la /storage/emulated/0/StS2LauncherRedux/Mods/
adb shell ls -la /storage/emulated/0/StS2LauncherRedux/Saves/

# 완전 초기화 (모든 데이터를 지우고 새 사용자처럼 시작)
adb shell pm clear dev.aldis.sts2launcherredux
adb shell rm -rf /storage/emulated/0/StS2LauncherRedux
```

`adb shell pm clear`는 일부 폰 (예: OnePlus/ColorOS)에서 막혀 있습니다. 실패하면 앱을 삭제한 뒤 다시 설치하세요. 이 명령은 Redux에만 적용되며, 이전 StS2 Launcher Mod의 폴더(`StS2LauncherMM`)는 건드리지 않습니다. 그 폴더는 직접 삭제하지 마세요.
